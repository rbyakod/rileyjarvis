◆ 00 · The verdict, up front

The critical finding first: this app has no separate TTS or STT calls to swap out. The entire voice feature is a single OpenAI Realtime WebRTC session (gpt-realtime-2, src/lib/realtime.ts + electron/main.cjs:643-698). Cloud VAD, cloud Whisper, cloud LLM and cloud TTS all arrive bundled over that one connection. Recommended route: all-JS, in the Electron renderer — kokoro-js (WebGPU) for TTS, @huggingface/transformers (ONNX Whisper, WebGPU) for STT, @ricky0123/vad-web (Silero) for turn detection, behind a new VoiceProvider seam so the existing Realtime client stays as a fallback toggle. LLM remains a plain chat-completions call for now (Phase 4 can swap in Ollama for 100% offline). Everything downloads on first run (~250–450 MB), then works with the network unplugged.

02

What “local” must re-create

Each thing the Realtime session silently does for us today needs an explicit local counterpart:

Realtime gives us…Local replacementNotes
semantic_vad turn detection + speech_started/stopped events Silero VAD via @ricky0123/vad-web ONNX model ~2 MB, runs in renderer on 16 kHz frames. Gives onSpeechStart / onSpeechEnd(audio) — the audio arrives already resampled to 16 kHz Float32, which is exactly Whisper's diet. (It's an energy+model VAD, not “semantic” — slightly dumber turn boundaries, tuned with a silence threshold.)
Server-side Whisper transcription Whisper — ONNX in renderer (transformers.js) or whisper.cpp native Per-utterance (not streaming) transcription of VAD-segmented audio. VAD-gating avoids Whisper's classic silence-hallucination problem.
gpt-realtime-2 as the conversational brain with 30 tools chat completions with the same instructions + tool specs Not part of “voice” per se, but the loop must exist somewhere. Keep OpenAI chat for now (new llm:chat IPC in main, key stays in main) — or Ollama later for full offline.
TTS voice cedar, streamed as audio deltas Kokoro-82M via kokoro-js 82M-param TTS, Apache-2.0 weights, 24 kHz output, faster-than-real-time on M3 Pro. Sentence-level generation instead of token streaming; visemes keep working because they're driven by output-audio energy, not by Realtime events.
Barge-in (interrupt_response: true) our own: VAD start while speaking → stop source node + abort LLM fetch ~15 lines. Mic already runs with echoCancellation: true (realtime.ts:105), so Ricky's own voice won't self-trigger the VAD.
Mood machine (listening/thinking/speaking/idle from server events) our own state flips at each stage boundary The four stages map 1:1 to VAD start → transcribe done → TTS playing → playback ended.
◆ gotcha worth knowing before you start

The typed-input path (sendText, realtime.ts:167) is a convenient backdoor for phasing: it already proves text → brain → response works without mic audio. That's why the plan below builds local TTS first (typed input only), then adds the mic loop — you get a talking local Ricky before you ever fight a VAD.

04

Three ways to wire it in

A

All-JS in the renderer

◆ RECOMMENDED

kokoro-js + transformers.js Whisper + Silero VAD, all via ONNX Runtime Web (WebGPU on this M3 Pro, wasm fallback). No child processes, no Docker, no Python. New dependency set is three npm packages.

Pros

  • One runtime story; models cached in the renderer's cache dir after first download
  • Zero packaging pain — ships like any other JS dep
  • Provider lives next to realtime.ts and drives the same callbacks
  • Truly offline after first run

Cons

  • Whisper-on-WASM is the slowest Whisper variant (WebGPU recovers most of it — benchmark in Phase 0)
  • ~250–450 MB first-run download needs progress UI
  • WebGPU in Electron needs a capability check + wasm fallback path
B

Native engines in the main process

whisper.cpp (via smart-whisper addon or a spawned binary, Metal-accelerated) for STT; Kokoro via kokoro-js on Node's CPU backend or a small Python sidecar. Audio crosses the existing preload bridge as ArrayBuffers.

Pros

  • Fastest STT outside MLX; whisper.cpp + Metal is excellent on Apple Silicon
  • Renderer stays thin — heavy inference off the UI thread

Cons

  • Native module rebuilds against Electron's ABI; asarUnpack for .node/binaries/models
  • More moving parts to sign, notarize, and debug
  • Premature until Option A is measured and found wanting
C

Local OpenAI-compatible servers

Run Kokoro-FastAPI (TTS, /v1/audio/speech, <1 s first token on M3 Pro) and Speaches or LocalAI (STT, /v1/audio/transcriptions); point the app at localhost. Least new app code per capability — but the loop (VAD, turn-taking, barge-in) is still yours to build, so the saving is smaller than it looks.

Pros

  • Battle-tested servers; OpenAI-shaped requests; swappable engines behind ports
  • Models live outside the app; renderer changes stay tiny

Cons

  • “Completely local” now includes “keep two services running” — worst daily-driver ergonomics
  • Docker on macOS adds overhead; uv/Python adds a runtime to install
  • File-upload HTTP round-trips add latency vs in-process
A · in-renderer JSB · native in mainC · local servers
Voice latencygood (WebGPU) / OK (wasm)bestgood, +HTTP hop
Packagingtrivialhard (native modules)n/a (external)
Code churnmoderate, containedmoderate + IPCsmall app-side, ops outside
Offline after setupyesyesyes, if services auto-start
Distribution size+~0.5 GB models (cached)+models +binariesapp stays small

Decision rule: build A. If renderer Whisper latency disappoints after Phase 0's benchmark, only the STT box swaps to B (whisper.cpp) — the provider seam keeps that a local change. C is what you'd pick if Ricky ever becomes a fleet service instead of a desktop app.

The loop, in code sketches

1 · Mic → VAD → Whisper — the entire STT side is two objects
import { MicVAD } from "@ricky0123/vad-web";
import { pipeline } from "@huggingface/transformers";

// VAD owns the mic. onSpeechEnd hands us Float32Array @ 16 kHz — exactly
// what Whisper wants, so no AudioWorklet/resampling code is needed.
this.vad = await MicVAD.new({
  stream: await navigator.mediaDevices.getUserMedia({
    audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true },
  }),
  onSpeechStart: () => this.bargeIn(),          // user talks mid-reply → interrupt
  onSpeechEnd:   (audio) => this.transcribe(audio),
});

// Whisper, WebGPU with automatic wasm/q8 fallback:
this.asr = await pipeline("automatic-speech-recognition",
  "onnx-community/whisper-base", { dtype: "q8", device: "webgpu" });

async transcribe(audio: Float32Array) {
  this.callbacks.onMood?.("thinking");
  const { text } = await this.asr(audio, { chunk_length_s: 30, stride_length_s: 5 });
  if (text?.trim()) {
    this.callbacks.onTranscript?.({ role: "user", text });   // same shape as realtime.ts:223-227
    await this.think(text);
  }
}
2 · Brain — new IPC handler in main, cloned from the existing vision handler
// electron/main.cjs — sits beside the gpt-4o vision handler (821-876).
// Key stays in main; renderer never sees it. Same loop shape the Realtime
// session ran internally: model → tool_calls → execute → re-call, ≤ N rounds.
ipcMain.handle("llm:chat", async (_e, { messages }) => {
  for (let round = 0; round < 4; round++) {
    const res = await fetch("https://api.openai.com/v1/chat/completions", {
      method: "POST",
      headers: { Authorization: `Bearer ${process.env.OPENAI_API_KEY}`, "Content-Type": "application/json" },
      body: JSON.stringify({
        model: "gpt-4o",
        messages: [{ role: "system", content: RICKY_INSTRUCTIONS }, ...messages],  // same instructions, main.cjs:19-47
        tools: toolSpecs,                                            // same 30 specs, main.cjs:49-435
      }),
    }).then(r => r.json());
    const msg = res.choices[0].message;
    if (!msg.tool_calls?.length) return msg.content;
    messages.push(msg);
    for (const call of msg.tool_calls) {
      const out = await runTool(call);             // the dispatcher behind tools:execute
      messages.push({ role: "tool", tool_call_id: call.id, content: JSON.stringify(out) });
    }
  }
});
// Phase 4: swap the URL for http://localhost:11434/v1/chat/completions (Ollama) — nothing else changes.
3 · Kokoro → speakers → mouth — the viseme meter survives untouched
import { KokoroTTS } from "kokoro-js";

this.tts = await KokoroTTS.from_pretrained("onnx-community/Kokoro-82M-v1.0-ONNX",
  { dtype: "q8", device: "webgpu" });        // fp32 if quality > speed; wasm works too

async think(userText: string) {
  const reply = await window.ricky.llmChat(this.history);   // IPC from sketch 2
  this.callbacks.onTranscript?.({ role: "assistant", text: reply });
  const speech = await this.tts.generate(reply, { voice: "af_heart" });
  this.speak(speech.audio, speech.sampling_rate);   // Float32Array @ 24 kHz
}

speak(float32: Float32Array, sampleRate: number) {
  this.stopPlayback();
  const buf = this.ctx.createBuffer(1, float32.length, sampleRate);
  buf.copyToChannel(float32, 0);
  this.source = this.ctx.createBufferSource();
  this.source.buffer = buf;
  this.analyser = this.ctx.createAnalyser();          // fftSize 1024, smoothing 0.72 —
  this.source.connect(this.analyser).connect(this.ctx.destination);
  this.source.onended = () => this.callbacks.onMood?.("idle");
  this.source.start();
  this.callbacks.onMood?.("speaking");
  this.startVisemeLoop(this.analyser);               // reuse the RMS/band math from realtime.ts:334-359 verbatim
}

bargeIn() {                                          // the local stand-in for interrupt_response
  if (this.mood === "speaking") { this.source?.stop(); this.llmAbort?.abort(); }
  this.callbacks.onMood?.("listening");
}

Deps for the whole thing: npm i kokoro-js @huggingface/transformers @ricky0123/vad-web. Note speech.audio gives raw samples, which is what we want — toBlob()/WAV encoding is only needed if audio ever crosses IPC as a file (Option B).

Picking a voice for Ricky

Realtime's cedar disappears with the migration. Kokoro ships ~20 English voices; the naming is <lang><gender>_name (a=US, b=UK; f/m). A short tasting flight for an assistant persona:

VoiceCharacterTry it as…
af_heartwarm, natural female — Kokoro's flagshipdefault recommendation
am_michael / am_adamneutral-to-deep maleclosest cousins of a “cedar”-style neutral male
am_puckplayful maleleans into Ricky's cheeky persona
af_sky / af_bellabright / clear femalemore energy, good over music/sfx

Voice files are tiny per-voice downloads; swapping is a string constant. Blends are also possible in some runtimes (af_heart(2)+af_sky(1) style), worth exploring once the basics work.
